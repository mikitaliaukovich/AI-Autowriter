# Голосовой авто-райтер для Word — краткое резюме

Полный отчёт (на английском): [`docs/feasibility-voice-autowriter.md`](../feasibility-voice-autowriter.md)

## Вывод

**Реализуемо** — как надстройка для **Word в браузере (Word on the web)** плюс
локальный сервис-компаньон (sidecar) с моделями на машине пользователя.
Ни один из пяти критериев не блокируется отсутствием технической возможности.

Google Docs исключён: надстройки Google Docs в принципе не получают доступ к
микрофону, поэтому критерий «всегда слушать» там недостижим.

## Критерии приёмки

| № | Критерий | Вывод |
|---|----------|-------|
| 1 | Постоянное прослушивание | **Реализуемо.** Микрофон в панели задач через `Office.devicePermission`, поток фильтруется Silero VAD |
| 2 | Мысли вслух не попадают в текст | **Реализуемо, самая сложная часть по UX.** Буфер ожидания + окно удержания + класс намерения ASIDE |
| 3 | Голосовое редактирование | **Реализуемо, наибольший объём разработки.** Индекс недавних предложений + типизированные операции правки + перегенерация предложения целиком |
| 4 | Шум и команды не попадают в текст | **Реализуемо с оговорками.** Пять слоёв фильтрации; остаточный риск — команда, принятая за диктовку |
| 5 | Продолжение фразы после паузы | **Реализуемо, но локальные модели требуют доработки.** Состояние «незакрытого предложения» + сшивка через LLM |

## Архитектура

Панель задач Word (браузер) — микрофон, VAD, состояние документа, применение
правок через Word JS API. Локальный sidecar — распознавание речи и языковые
модели, без состояния и без доступа к документу.

- **Распознавание речи:** `parakeet-tdt-0.6b-v3` (CC-BY-4.0, 25 языков включая
  русский, потоковый режим, тайминги по словам) как основная модель;
  **GigaAM v3** (MIT, Сбер) — вариант с лучшим качеством на русском
  (≈3.3% WER против ≈7.9% у Whisper large-v3 на CPU), со встроенной пунктуацией.
- **Языковые модели:** маленькая (1–4B, Vikhr / Qwen3-4B) для классификации
  намерений на горячем пути, большая (8–14B, Qwen3 / T-lite / T-pro) для
  генерации правок и сшивки предложений. Запуск через Ollama.
- **Стоимость:** локальные модели — нет оплаты за час использования. Требования
  к железу: минимум 16 ГБ ОЗУ (CPU), комфортно — GPU 12–16 ГБ VRAM или Apple
  Silicon с 24 ГБ+.

## Ключевое требование к правкам

Пример: *«Она была феей. Нет, исправь на она была ведьмой»* — в документе должно
остаться **«Она была ведьмой»**, без следов команды.

Главное правило: **в русском языке замена слова не является заменой подстроки.**
«фея» → «ведьма» меняет падеж («была феей» → «была ведьмой»), а другие правки
меняют согласование по всей фразе. Поэтому модель всегда возвращает **полностью
переписанное предложение**, а не отдельное слово.

Большинство самоисправлений происходит, пока текст ещё находится в буфере
ожидания и не попал в документ — тогда правка сводится к операции над строкой, а
слово «фея» в документе не появляется вообще.

## Главные риски

1. **Связь панели задач с локальным sidecar.** Страница отдаётся по HTTPS, а
   `ws://localhost` блокируется как смешанный контент. Решение — `wss://` с
   локально доверенным сертификатом (подход mkcert). Это первое, что нужно
   проверить.
2. **Только браузеры на Chromium.** `DevicePermission 1.1` не работает в Firefox
   и Safari.
3. **Разрешение на микрофон нельзя отозвать из продукта** — только удалением
   надстройки или очисткой кэша браузера. Компенсируется явным индикатором записи
   и жёстким выключением микрофона в панели.

## Рекомендуемый порядок работ

0. **Проверочные эксперименты:** микрофон в панели задач Word; `wss://` до
   localhost. Если второй не проходит — локальная архитектура нежизнеспособна.
1. Диктовка с буфером ожидания (критерии 1, 2, 4).
2. Редактирование, начиная с самоисправлений (критерий 3).
3. Продолжение фразы после паузы (критерий 5).
4. Верификация говорящего, поддержка десктопного Word через нативный sidecar.
